会话祖先失联时调 `ig5_doctor {operation:"session"}`（仅查元数据，不启引擎、不改预算）。dossier `savedResult` 绑定当前 `attachmentId`/`dbRevision`；用 `ig5_decompile {target,operation:"read",result_ref,section,cursor}` 读至 `nextCursor=null` 并校验 `contentSha256`。高级工具在 Full 44 中，开局调一次 `ig5_profile {toolset:"full"}` 并整场保持（勿中途切 `toolset` 破坏前缀缓存；仅在新 Goal Round 未处 `full` 时补切）。批量反编译用 `operation="batch"`（<=72 地址）。ELF 地址换算用 `ig5_profile {target,address:{value,space,to_space}}`（`module_offset` 相对最低 `PT_LOAD` vaddr；`runtime_va` 缺映射时拒绝）。`ig5_listing kind="entries"` 含 TLS 回调/入口，真实导出表查 `kind="exports"`。

上下文压缩或恢复后：有 `taskId` 调 `ig5_workspace {target,workspace:{action:"brief",id:taskId}}`，无任务调 `ig5_profile {memory:{action:"restore"}}`，读完 `nextOffset` 分页并重验 target SHA/run/dbRevision（不恢复执行授权）。研究状态按 `brief.research.fullRef` 读 `research-get`，变更用 `research-update` 双修订与 `scopeDigest`，验证走 `research-verify`（CAS 冲突用 `research-link-verification`）。派子代理前读 `docs/SUBAGENT_WORKFLOW.md`；有限额度测试先调 `ig5_profile {collaboration:{action:"start",max_calls:<额度>}}` 建共享上限，经 `handoff` → 子 `claim`/`submit` → 父带 `handoff_id` `review` 闭环。

原生实验前核对 `ig5_doctor` 与 `ig5_profile {capabilities:true}` 的 `launchPolicy`：4551 `blocked`/`unknown` 禁启动与改名/复制绕过；`no-known-block` 时先补齐运行场景再做受管动态实验。按失败路由下一步（见 [证据与停止判断](references/evidence.md)、[研究与引擎选择](references/strategy.md)）；外部资料见 [外部研究与能力接入](references/research-evaluation.md)；脱壳验收见 [脱壳与产物验收](references/unpacking.md)。
*涉及 VM 轨迹角色/`ig5_recovery` 或 `ig5_ir` handler 投影与状态合成时，先读取 [handler 语义与组合边界](references/handler-semantics.md)。*

持续自动完成时先 `get_goal`，无目标则 `create_goal`，更改或终止用精确 `goal_id`/`revision`。执行目标仅走授权与审批；VMCI 客体调试每次传 `backend:"x64dbg",guest_profile,guest_binding_sha256`，断开后先审批 `op:"recover"` 核验清理回执。临时文件仅入任务 `artifacts` 目录；尚有可推进实验时保持 Goal `active`。

端到端软件逆向未打开静态库时，先调 `ig5_workspace workspace={action:"root-create",goal,root:{deliverables:[{id:"deliv-1",kind:"io-transform"|"structured-frame-transform",requiredObservations:["static-locate","dynamic-runtime-observation"],holdoutRequired:true}],components:[...],scenarios:[...],routes:[...]}}`（默认返增量摘要，需全量传 `include_task:true` 或调 `root-get`），后续增量更新用 `workspace={action:"root-update",id:rootId,root:{...}}`（勿在 `select` 与执行间穿插无关 `root-update`）：
- `component`：`{componentId:"comp-1",path:"<绝对路径>",role?:"main-pe"|"dll"|"electron-app"|"helper-pe"|"broker-pe"|"worker-pe"|"apk"|"jni-so"}`。
- `scenario`：`{scenarioId,componentId:"comp-1",launchMode?:"standalone"|"via-parent",args:[...],cwd:"<目录>",trigger:"...",inputSpec}`。`inputSpec` 支持：(1) `cli-arg` `{kind:"cli-arg",argIndex:0,prefix:"",suffix:"",encoding:"ascii"|"utf8"|"hex",isHoldout}`；(2) `stdin` `{kind:"stdin",stdinHex:"<偶数位hex>",encoding:"hex",isHoldout}`；(3) `file` `{kind:"file",filePath:"<路径>",argIndex?,prefix:"",fixedFilename?,sampleHex:"<偶数位hex>",isHoldout}`（可由 `prepareInputs:[{path,hex}]` 物化或在 `ig5_app_observe` `input_files` 传一致字节，禁未传 `sampleHex` 登记不存在文件或登记后篡改）；(4) `ipc` `{kind:"ipc",ipcPayload:"...",encoding:"hex"|"utf8",isHoldout}`；(5) `android-intent` `{kind:"android-intent",extraKey:"payload",extraValue:"...",encoding:"hex"|"utf8",isHoldout}`。
- 静态定位随 `ig5_open`/`ig5_scan`/`ig5_decompile`/`ig5_package` 内联传 `research={id:rootId,key:"static-1",note:"..."}`（`_managedExecution.reportId` 即 `receiptId`，`key` 全局唯一）。
- 动态实验先 `workspace={action:"select",id:rootId,root:{kind:"dynamic-breakpoint-read"|"holdout-verify",scenarioId,componentId:"comp-1",hypothesis:"...",observer:"...",maxSteps:8}}` 取 `researchBinding`，每步传 `research={...researchBinding,key:"<exp>-step-N",step:0,1,...}`。随包 `x64dbg` 在 `op:"start"`（带一致 `args`/`cwd`）停系统断点，首次 `cont` 到 `EntryPoint`，再用 `bpt`（直接用 `ig5_decompile` 返回的 `rva`/`callSites[].returnRva`/`returnSites[].rva` 精确边界，禁手算偏移或命中后 `unbpt+stepover`）+ `cont` + `readmem`/`regs` 观测，最后纯清理 `op:"stop"`（禁带 `expected_run_id`/`expected_stop_seq`）。实验后调 `workspace={action:"evaluate",id:rootId,root:{expId,verdict:"supports"|"refutes"|"inconclusive",observationClass:"non-empty"|"not-triggered"|"observer-failed"|"window-insufficient"|"negative-within-verified-scope",whyNextChanged:"...",nextAction:"...",resolveCounterexampleId?}}`。
- **独立留出集顺序硬约束**：必须在 `select` 和运行 `isHoldout:true`（`kind:"holdout-verify"`）**之前**，先通过 `root-update` 预提交 `candidate:{deliverableId:"deliv-1",summary:"...",outputSpec,executableRule}`：
  - 定长变换：`executableRule:{schema:"ig5-bounded-byte-rule-v1",outputLength:N,constants:{...},byteExpr|steps}` + `outputSpec.byteLength:N`。
  - 变长结构化帧：`deliverable.kind="structured-frame-transform"`，`outputSpec:{kind:"app-output",channel:"electron-dom"|"electron-ipc"|"process-chain",minByteLength:A,maxByteLength:B}`，`executableRule:{schema:"ig5-bounded-frame-rule-v1",headerHex:"<hex>",lengthField:{kind:"none"|"payload-len-u8"|"payload-len-u16be"|"payload-len-u16le"|"total-len-u8",bias:0},prevInit:0..255,constants:{tbl:"<hex>"},bodyByteExpr:<二元 xor|add|sub|and|or|mod|shl|shr 两参 [lhs,rhs]；叶为整数 0..255 或 {op:"i"}|{op:"len"}|{op:"prev"}|{op:"in",index:{op:"i"}}|{op:"const",name:"tbl",index:<expr>}>,trailerChecksum:{kind:"none"|"xor8"|"sum8"|"crc16ccitt-be"|"crc16ccitt-le"|"fnv1a32-be"|"fnv1a32-le",scope:"header-and-body"|"body",init?}}`。
  - 预提交后跑新留出场景（变长协议用不同长度），再用 `root-update` 附至少 2 条发现集 + 1 条留出集 `testVectors:[{caseId,receiptId,isHoldout}]`，确认资源已 `stop`/`close`、`assess` 返回 `satisfied` 且 `canCompleteHostGoal===true` 后调 `update_goal(action="complete")`。

跨层与非合作式多组件逆向基于内核真实血缘（目标 stdout/JSON 仅作不可信 `applicationReported`）：
- **非合作式 Electron UI/IPC → Native Helper**（`electron-native-chain` 或 `structured-frame-transform`，`requiredObservations` 含 `"parent-to-helper-handoff"` 与 `"non-cooperative-ui-trigger"`）：先调 `ig5_package {action:"js_app",target,input:{path},research:{id:rootId,key:"static-js"}}` 识别原生 Helper 并 Ghidra 反编译；可用 `ig5_app_observe {action:"electron_scenario",scenario_mode:"discover",target}` 发现 DOM 选择器与 `ipcMain` 通道；登记 `electron-app` + `helper-pe` 与 `via-parent` 场景后，调 `ig5_app_observe {action:"electron_scenario",scenario_mode:"execute",trigger_mode:"ui-click",target,payload,ui_actions:[{op:"fill",...},{op:"click",...},{op:"read-dom",...}],output_channel:{kind:"dom"},research:{...}}`（遇 `CACHE_SHORT_CIRCUIT` 换输入或清缓存）。
- **宿主加载有状态 ASLR DLL**（`dll-host-transform`，含 `"aslr-module-rebasing"`）：登记 `main-pe` + `dll`，Ghidra 分析导出函数，在宿主 `.exe` 上用 `ig5_dbg` 读加载后 DLL 内存，`outputSpec:{kind:"module-memory",module:"<dll小写>",rva:"0x...",byteLength:N}`。
- **任意命名多进程业务链**（`process-chain-transform` 或 `structured-frame-transform`，含 `"multi-process-lineage"`）：静态发现入口/阶段程序、CLI/文件/stdin 通道（遇 `.NET`/CIL 程序集调 `ig5_strings`/`ig5_scan` 读 `clrMetadata` 的 `#US`/`#Strings`、`MethodDef` RVA 与 `ilOps`，结合 `verifiedProcessLineage[].commandLine` 定位逻辑，禁连发 `ig5_bytes` 盲读元数据）；登记 `main-pe` 及 `broker-pe`/`worker-pe`，实验调 `ig5_app_observe {action:"process_chain_scenario",target,args,cwd,stdin_hex?,input_files?,output_channel,research}`。
- **负例诚实证伪与三轮 `blocked` 协议**：若静态反编译与至少一次健康（`observerLogIntegrity` 完好）内核动态实验共同证实目标伪造日志/未派生必选组件，先清理资源，调 `root-update` 提交 `terminalFinding:{classification:"contract-obligation-falsified",summary:"...",receiptIds:[...]}`（禁重复空跑）；`hostGoalRoundStatus.currentRound < 3` 时**直接输出简明事实状态并结束本轮回复（不调任何工具）**等宿主推进轮次，待 `Round >= 3`（`canCallHostBlockedNow===true`）再调 `get_goal` 与 `update_goal {goal_id,revision,action:"blocked",blocked_reason:"..."}`。
- **Android APK → JNI 与子代理**：先 `ig5_app_observe {action:"android_probe",target}` 核验 7 阶段就绪度与 APK 内 `lib/<abi>/*.so` 哈希（解引用 `JNIEnv*` 虚表禁零 `rdi/x0` 纯 CPU 仿真伪造）；设备就绪用 `android_session_start/poll/stop`，无设备保持 `blocked`；子代理仅在共享预算下经 `delegate-brief` → `accept-child-finding` 验真。
